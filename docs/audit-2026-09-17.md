## 已复核属实的发现（按优先级）

### P0 — SSRF：DNS 校验与实际连接不绑定（converter.py:1308-1357）
`_url_is_safe_for_fetch` 预解析校验 IP，但 `_url_to_data_uri` :1356 把原始域名交给 httpx 重新解析连接——两次解析不绑定，存在 DNS rebinding 窗口。另 :1256 注释错误：100.64/10（CGNAT）不在 `is_link_local` 内。AGENTS.md 声称的防线「域名解析后逐个 IP 校验」只覆盖了第一次解析。
修法：传输层绑定已校验 IP（自定义 transport/解析器），并把 100.64/10 加入拒绝集。
影响：远程图片内联功能（默认开启）。

### P1 — 流式层四连（converter.py / anthropic_stream.py / responses_compat.py）
1. **上游错误被转成正常完成**：`_err_event`（converter:4445-4451）发出仅含 error 字段的 OpenAI chunk；anthropic_stream:175-177 因无 choices 直接忽略，:3259 finalize 收出正常 end_turn；responses_compat 无 error 检查且 :380 无条件 response.completed。上游 429/502 在客户端表现为「空回答正常结束」。
2. **并行工具分片重开块**：anthropic_stream:277 只维护单 active_tool_index，上游交错流式多工具时同一工具 ID 会被开成两个内容块，参数 JSON 拆碎。
3. **取消路径漏收尾**：collect_task（converter:3841-3846）无 finally 取消回收；`_stream_upstream` 只捕 httpx.HTTPError（:4397），客户端断开时 `_record_usage` 被跳过——AGENTS.md「所有完成路径统一落盘」不成立；共享流式客户端 `timeout=None`（:4354）无读超时兜底。
4. **降级误标记**：converter:4371 替换 body["model"]=fb 后，:4413-4414 对新值再次 `_mark_model_unavailable`，把实际服务成功的降级模型写进 runtime-11102 证据，污染模型清单（`_effective_unavailable` :964-969 消费）。

### P1 — Rust 侧（update.rs / lib.rs / agents.rs / proxy.rs）
5. **短 SHA vs 40 位 SHA 恒不等**（build.rs:23 短 SHA vs update.rs:289-302/356/389-394）：同 tip 也必走 compare；compare 失败时误报「有更新、数量未知」并按有更新缓存 24h——正是 AGENTS.md 里「点检查更新毫无反应」同款机制的反向误报。修法：烘焙完整 SHA，展示时再截短。
6. **设置保存先内存后磁盘**（lib.rs:298-300）：`*guard = settings` 成功、`save_app_config` 失败时内存与文件分叉，且非原子写（fs::write）。修法：先原子落盘成功再提交内存。
7. **hermes_is_configured 宽松兜底**（agents.rs:333-337）：任意非空 base_url + provider/model 即判「已接入」，端口严格匹配被绕过——违反 AGENTS.md「必须比对端口」铁律的本意。
   **〔外部交叉评审后精确化〕**：`is_our_proxy_url` 本身是严格的（agents.rs:134-171：仅 http 回环 + 端口比对 + 路径含 /v1，无端口即判否）——问题不在它，而在 `hermes_is_configured` 的 fallback 分支绕过了它。措辞已按此修正。
8. **proxy_rate_limit 调用点未统一 2xx 语义**（proxy.rs:744-753）：仅 200 算成功，201-299 会落到 Err 分支（分类器返回 None 时补造失败文案）。与 ed207c7 修复的其余调用点不一致。
   **〔外部交叉评审后降级 P2〕**：该端点是内部状态查询接口，现网契约以 200 为正常返回、老内核走 null 降级，属鲁棒性改进而非主线缺陷。
